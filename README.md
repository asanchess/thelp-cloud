# Private daily Telegram report engine

Generic public source; no Telegram messages, user identifiers, report artifacts or credentials are stored in this repository. Telegram and model credentials live only in encrypted GitHub Actions secrets. The state branch contains AES-256-GCM encrypted delivery receipts, never transcripts or reports. Decryption key is a separate repository secret. Logs contain status codes only.

Runs on standard GitHub-hosted Ubuntu runners. No paid runners, inference models, automatic top-ups or paid fallbacks. External inference uses only a fixed :free model through Phala, data_collection=deny, ZDR required, and max_price=0. If inference or validation fails, a pinned Apache-2.0 Qwen3-4B model runs directly on the same ephemeral runner via a checksum-verified llama.cpp engine. Input is processed in bounded batches, then a critical editor forms the short edition using complete selected conversations. Raw source-only substitutes and intermediate bot status messages are disabled. Every delivered edition must pass AI analysis and source checks. If both AI paths fail, the run records encrypted diagnostics and fails for a later retry, without a fake report. GitHub schedules may be delayed and may need reactivation after repository inactivity.

Daily trigger 03:37 UTC prepares yesterday's local day (UTC+5) and waits until 05:00 UTC to deliver. Recovery trigger 07:17 UTC retries undelivered editions. CPU inference may take longer; late starts deliver after preparation, exact 10:00 local delivery is not guaranteed. Manual smoke is explicitly a technical check, not a report. Reruns skip confirmed AI delivery parts; a prior source-only edition is archived before its AI replacement. Uncertain network results require manual reconciliation. No historical local checkpoint is modified.

Use a dedicated Telegram session for the cloud runner, never concurrently from a local client. A bot token cannot read the owner's private chat history. Revoked or expired user authorization requires a new interactive login; failures are reported distinctly to the owner. No code can bypass Telegram authorization.

Required secrets: TELEGRAM_API_ID, TELEGRAM_API_HASH, TELEGRAM_SESSION, TELEGRAM_OWNER_ID, TELEGRAM_BOT_TOKEN, OPENROUTER_API_KEY, STATE_ENCRYPTION_KEY (base64 32 random bytes). Never commit these values, local report files, snapshots, model requests or model responses. No pull-request trigger uses secrets. State writes target only the state branch, with single-job concurrency.

Report source is untrusted. No source instructions execute; inference has no tools or access to the runner. Exact quotes and every chat's coverage are verified before sending. Media are not downloaded or interpreted. Full HTML is escaped and blocks external resources. The brief PDF and full HTML are uploaded only to the configured owner's private bot conversation.

The offline model process receives no Telegram/GitHub/provider secrets, binds only 127.0.0.1, and has its output logs discarded. No model files or private report artifacts are uploaded or cached by Actions. The model-quality workflow uses only public synthetic messages and has no secret environment. See AGENT_ENVIRONMENT.md for the operating contract.
